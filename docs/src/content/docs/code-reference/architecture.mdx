## 概述

WinUtil 是一个基于 PowerShell 的 Windows 实用工具，带有 WPF（Windows Presentation Foundation）图形界面。本文档说明其架构、代码结构，以及各个组件之间如何协同工作。

## 总体架构

```
┌─────────────────────────────────────────────────────┐
│                    Winutil GUI                      │
│              (WPF XAML Interface)                   │
└──────────────────┬──────────────────────────────────┘
                   │
         ┌─────────┴─────────┐
         │                   │
┌────────▼──────┐   ┌───────▼────────┐
│  Public APIs  │   │  Private APIs  │
│  (User-facing)│   │   (Internal)   │
└───────┬───────┘   └───────┬────────┘
        │                   │
        └────────┬──────────┘
                 │
    ┌────────────▼────────────┐
    │   Configuration Files   │
    │  (JSON definitions)     │
    └────────────┬────────────┘
                 │
    ┌────────────▼────────────┐
    │   External Tools        │
    │  (WinGet, Chocolatey)   │
    └─────────────────────────┘
```

### 核心组件

#### 1. Compile.ps1
**用途**：把所有独立的脚本文件合并为一个 `winutil.ps1`，便于分发。

**流程**：
1. 从 `/functions/` 读取所有函数文件
2. 包含配置 JSON 文件
3. 嵌入 XAML GUI 定义
4. 合并为单个脚本
5. 输出 `winutil.ps1`

**原因**：分发更简单（单文件），同时提升加载速度。

#### 2. scripts/main.ps1
**用途**：管理整个运行过程的入口点。

**职责**：
- 加载配置
- 执行无界面的 `-Preset` 与 `-Config` 路径
- 在专用的 STA 运行空间（Runspace）上启动界面并等待其结束
- 上报界面线程抛出的任何异常，然后进行清理

界面本身位于 `Start-WinUtilUserInterface`，而不是这里。参见 [线程模型](#threading-model)。

#### 3. functions/public/
**用途**：面向用户的函数，实现各项主要功能。

**关键函数**：
- `Initialize-WPFUI.ps1`：初始化 GUI
- `Invoke-WPFTweak*`：应用系统优化项
- `Invoke-WPFFeature*`：启用 Windows 功能
- `Install-WinUtilProgram*`：安装应用程序

**命名约定**：函数名以 `WPF` 或 `Winutil` 开头，以便被加载到运行空间（Runspace）中。

#### 4. functions/private/
**用途**：不直接由用户调用的内部辅助函数。

**关键函数**：
- `Get-WinUtilVariables.ps1`：获取 UI 元素引用
- `Install-WinUtilWinget.ps1`：确保已安装 WinGet
- `Get-WinUtilCheckBoxes.ps1`：获取复选框状态
- `Invoke-WinUtilCurrentSystem.ps1`：获取系统信息

#### 5. config/*.json
**用途**：以声明方式定义可用的应用程序、优化项和功能。

**文件**：
- `applications.json`：应用程序定义，包含 WinGet/Choco ID
- `tweaks.json`：注册表优化项及其撤销操作
- `feature.json`：可启用/禁用的 Windows 功能
- `preset.json`：预定义的优化项组合
- `dns.json`：DNS 提供商配置

#### 6. xaml/inputXML.xaml
**用途**：WPF GUI 的布局与设计。

**结构**：
- 带事件处理程序的按钮
- 用于输入的文本框
- 用于选项的复选框
- 用于选择的列表框

## Win11 Creator 架构

**Win11 Creator** 是 Winutil 中一个专用子系统，用于创建定制的 Windows 11 ISO。它独立于主程序包安装与优化项系统运行。

### Win11 Creator 组件

**核心函数**（`functions/private/`）：
- `Invoke-WinUtilISO.ps1`：主编排器，包含 ISO 工作流及辅助函数
  - `Invoke-WinUtilISOBrowse`：ISO 文件选择对话框
  - `Invoke-WinUtilISOMountAndVerify`：校验并挂载 ISO，确认它是官方 Windows 11 ISO
  - `Invoke-WinUtilISOModify`：在后台运行空间（Runspace）中启动修改
  - `Invoke-WinUtilISOExport`：通过 `oscdimg.exe` 构建可启动 ISO
  - `Invoke-WinUtilISOCheckExistingWork`：恢复未完成的工作会话
  - `Invoke-WinUtilISOCleanAndReset`：清理临时目录并重置界面
  - `Write-WinUtilISOLog`：向界面状态框与会话日志发送日志消息
  - `Set-WinUtilISOStep`：控制向导的导航状态
  - `Get-WinUtilEditionIdFromName`：把版本显示名称映射为安装程序的版本 ID
  - `Invoke-WinUtilRobocopy`：复制文件并校验退出码
  - `Find-WinUtilOscdimg` / `Get-WinUtilOscdimgPath`：定位或安装 `oscdimg.exe`

- `Invoke-WinUtilISOUSB.ps1`：U 盘检测与格式化
  - `Invoke-WinUtilISORefreshUSBDrives`：枚举 U 盘
  - `Get-WinUtilFreeDriveLetter`：查找可用的驱动器号
  - `Invoke-WinUtilISOWriteUSB`：把 U 盘格式化为 GPT/FAT32，必要时拆分 WIM，并复制文件

- `Invoke-WinUtilISOScript.ps1`：准备安装介质与自定义内容
  - 把 AppX 卸载（19 个预装软件包）暂存进 `autounattend.xml`，在首次登录时执行
  - 在 Windows 安装过程与首次登录时应用 50 多项注册表优化；首次登录时移除计划任务
  - 在首次登录时触发 OneDrive 卸载
  - 把安装脚本回退方案暂存到 `sources\$OEM$\$$\Setup\Scripts\`
  - 在 `autounattend.xml` 中固定所选版本，并写入 `sources\ei.cfg`
  - 若已启用，则把当前系统符合条件的驱动程序注入 WIM 映像（仅在驱动维护时挂载 WIM）

### Win11 Creator 数据流

```
User selects official Windows 11 ISO
    ↓
Invoke-WinUtilISOBrowse → OpenFileDialog, validates file size
    ↓
Invoke-WinUtilISOMountAndVerify
    ├─ Mount ISO via Mount-DiskImage
    ├─ Verify install.wim or install.esd exists
    ├─ Check for "Windows 11" in image metadata
    ├─ Extract available editions (Home, Pro, Enterprise, etc.)
    └─ Store ISO path, drive letter, WIM path, image info in $sync
    ↓
User optionally enables the Driver Injection checkbox
    ↓
Invoke-WinUtilISOModify (runs in background runspace)
    ├─ Create work directory: ~WinUtil_Win11ISO_[timestamp]
    ├─ Copy ISO contents to disk via robocopy (~5-6 GB)
    ├─ Invoke-WinUtilISOScript:
    │   ├─ Generate autounattend.xml with Windows PE and specialize safeguards
    │   ├─ Add first-logon script (19 AppX removals, registry tweaks, OneDrive uninstall)
    │   ├─ Pin selected edition index in autounattend.xml (/IMAGE/INDEX)
    │   ├─ Stage setup script fallbacks to sources\$OEM$\$$\Setup\Scripts\
    │   ├─ Write sources\ei.cfg and remove stale sources\PID.txt
    │   └─ If driver injection enabled:
    │       ├─ Require install.wim; install.esd cannot accept driver injection
    │       ├─ Export current system drivers via DISM
    │       ├─ Exclude stale duplicate packages
    │       ├─ Inject storage drivers into boot.wim index 2 and eligible drivers into install.wim
    │       └─ Validate WIM metadata before and after injection
    ├─ Dismount source ISO
    └─ Report completion, enable export options
    ↓
Invoke-WinUtilISOExport (user chooses output)
    ├─ Option 1: Save as ISO
    │   ├─ Build bootable ISO via oscdimg.exe (BIOS/UEFI dual-boot)
    │   └─ Output: Win11_Modified_[date].iso (close to the source ISO size)
    │
    └─ Option 2: Write to USB
        ├─ Format USB as GPT
        ├─ Create single FAT32 partition (capped at 32 GB)
        ├─ Split install.wim into .swm files if > 3.8 GB
        ├─ Reject install.esd files of 4 GB or more
        ├─ Copy files via robocopy
        └─ Output: Bootable USB (minimum 8 GB)
    ↓
Invoke-WinUtilISOCleanAndReset (optional)
    ├─ Dismount any open WIM mounts with discard
    ├─ Delete temp working directory (~10-15 GB)
    └─ Reset UI to initial state
```

### Win11 Creator 校验与安全

**ISO 校验**：
- 只接受微软官方的 Windows 11 ISO
- 校验 install.wim 或 install.esd 是否存在
- 检查映像元数据中是否包含 “Windows 11” 字符串
- 拒绝自定义的、已修改的或非 Windows 11 的 ISO

**WIM 元数据校验**：
- 驱动注入期间，`Assert-WinUtilISOWimMetadata` 会在 WIM 维护前后校验关键字段（`Languages`、`Installation`、`Edition`、`ProductSuite`、`ProductType`）
- 若缺少必需元数据或元数据发生变化，驱动注入会在导出之前中止
- 未启用驱动注入时，WinUtil 会保留原始安装映像，并跳过 WIM 元数据校验

**版本固定与安装回退**：
- 写入 `sources\ei.cfg` 并删除 `sources\PID.txt`，使安装程序不会使用不匹配的 OEM 产品密钥
- 在 `autounattend.xml`（`/IMAGE/INDEX`）中固定所选版本的索引
- 在 `sources\$OEM$\$$\Setup\Scripts\` 下暂存回退安装脚本，并启用 `UseConfigurationSet`

**工作会话恢复**：
- 自动检测上一次会话中未完成的工作
- 允许直接恢复导出步骤，无需重新执行选择与修改
- 避免重复修改

**修改安全性**：
- Windows PE 与 specialize 阶段设置了硬件绕过与安装保护；`WinUtil-PostInstall.ps1` 在首次登录时应用额外的注册表更改
- 原始 ISO 从不被修改，只修改工作副本
- 记录到 WinUtil 会话日志以及实时界面状态面板
- DISM 负责映像卸载，出错时自动清理并放弃更改

### Win11 Creator 注册表优化

`Invoke-WinUtilISOScript` 函数会在安装过程与首次登录时应用 **50 多项注册表优化**：

**硬件绕过**：
- 绕过 TPM 2.0 检查
- 绕过安全启动要求
- 绕过 CPU 兼容性检查
- 绕过内存（RAM）要求
- 绕过存储检查

**隐私与遥测**：
- 禁用广告 ID
- 禁用个性化体验
- 禁用输入个性化
- 禁用语音在线隐私
- 禁用云内容建议
- 禁用应用建议订阅
- 移除 CEIP、Appraiser、WaaSMedic 等

**OOBE 与安装**：
- 启用本地账户设置
- 跳过 Microsoft 账户要求
- 默认深色模式
- 清空任务栏与开始菜单

**安装后处理**：
- 阻止 DevHome 自动安装
- 阻止新版 Outlook Mail 应用安装
- 阻止 Teams 自动安装

**系统功能**：
- 禁用 BitLocker 与设备加密
- 从任务栏移除 Chat 图标
- 禁用 OneDrive 文件夹备份
- 禁用 Copilot
- 在 OOBE 期间禁用 Windows 更新（首次登录时重新启用）

### 驱动注入功能

**可选增强**：启用后，会从当前运行的系统导出所有驱动程序，并注入到：
- `install.wim`（主系统映像），排除过时的重复项
- `boot.wim` 索引 2（Windows 安装 PE 环境），仅注入存储控制器（`SCSIAdapter` / `HDC`）

**使用场景**：用于在缺少驱动程序的系统上完成离线安装。

### 磁盘空间需求

- **临时工作目录**：约 10-15 GB
- **原始 ISO**：4-6 GB
- **修改后的 ISO**：接近源 ISO 的大小
- **总计需要**：约 25 GB，以确保操作安全

## 配置文件格式

### applications.json 结构

```json title="config/applications.json"
{
  "WPFInstall<AppName>": {
    "category": "Browsers",
    "choco": "googlechrome",
    "content": "Google Chrome",
    "description": "Google Chrome browser",
    "link": "https://chrome.google.com",
    "winget": "Google.Chrome"
  }
}
```

**字段**：
- `category`：属于 Install（安装）选项卡中的哪个分类
- `content`：GUI 中的显示名称
- `description`：提示/说明文本
- `winget`：WinGet 包 ID
- `choco`：Chocolatey 包名
- `link`：官方网站

### tweaks.json 结构

```json title="config/tweaks.json"
{
  "WPFTweaksTelemetry": {
    "Content": "Disable Telemetry",
    "Description": "Disables Microsoft Telemetry",
    "category": "Essential Tweaks",
    "panel": "1",
    "registry": [
      {
        "Path": "HKLM:\\SOFTWARE\\Policies\\Microsoft\\Windows\\DataCollection",
        "Name": "AllowTelemetry",
        "Type": "DWord",
        "Value": "0",
        "OriginalValue": "1"
      }
    ]
  }
}
```

**字段**：
- `Content`：显示名称
- `Description`：作用说明
- `category`：Essential/Advanced/Customize
- `registry`：要进行的注册表更改
- `registry[].Values`：注册表支持的下拉框在各个状态下的取值
- `registry[].DefaultValue`：注册表项不存在时生效的值
- `service`：要更改的服务
- `OriginalValue/State`：用于撤销功能

## 线程模型

WinUtil 运行在三类线程上，每类线程各司其职：

| 线程 | 运行空间（Runspace） | 职责 |
| --- | --- | --- |
| 主线程 | 脚本启动时所在的那个线程 | 启动界面、等待其结束、上报界面错误、清理 |
| 界面线程 | `$sync.UIRunspace`，一个专用的 STA 运行空间 | 拥有窗口。只负责绘制与调度，不做其他事 |
| 工作线程 | `$sync.runspace`，一个共享池 | 执行所有耗时任务：安装、优化项、功能、AppX、Win11 Creator |

这三类线程都由同一个起点 `New-WinUtilSessionState` 创建，它携带着 `$sync`、已编译脚本的全局变量以及所有 WinUtil 函数。正因如此，任意线程都能调用任意辅助函数，而无需调用方注入函数定义。

```powershell
# main.ps1 - the interface gets its own thread
$sync.UIRunspace = [runspacefactory]::CreateRunspace($Host, (New-WinUtilSessionState))
$sync.UIRunspace.ApartmentState = "STA"
$sync.UIRunspace.Open()

$uiShell = [powershell]::Create()
$uiShell.Runspace = $sync.UIRunspace
[void]$uiShell.AddScript({ Start-WinUtilUserInterface })
$uiHandle = $uiShell.BeginInvoke()
$uiHandle.AsyncWaitHandle.WaitOne()
```

**原因**：窗口永远不会因为工作而阻塞，界面线程上发生的故障会被上报，而不是无声消失。

## 长时间运行的任务

每个耗时操作都经由 `Start-WinUtilJob`，它掌管运行中的操作所需的一切：拒绝在已有作业运行时启动、忙碌标志（`$sync.ActiveJob`）、进度条与任务栏项、带框的控制台横幅、日志中的开始/完成/失败记录，以及无论发生什么都在 `finally` 中恢复界面。

`Invoke-WPFButton` 决定什么算作耗时操作。任何会更改系统的操作都会启动一个作业；只改变界面显示内容的操作则在界面线程上运行。正是这一种分类，使得任何工作流都不必自行安排进度、横幅或忙碌状态。

```powershell
Start-WinUtilJob -Name "Features" -Description "Installing Windows Features" -Parameters @{
    Features = @($sync.selectedFeatures)
} -ScriptBlock {
    param($Features)

    $total = @($Features).Count
    $completed = 0
    foreach ($feature in $Features) {
        $completed++
        Step-WinUtilJob -Status "Installing $feature ($completed/$total)" -Percent ([int](($completed / $total) * 100))
        Invoke-WinUtilFeatureInstall $feature
    }
}
```

作业主体只需要完成工作并调用 `Step-WinUtilJob`。它抛出的任何异常都会被捕获、记录，并在任务栏上标记为失败。

**传值，而非闭包**：作业主体会在工作线程内按文本重建，因此它通过 `-Parameters` 接收所需内容，而不是捕获调用方的变量。

## 错误处理与日志

作业主体不需要自己的错误处理。`Start-WinUtilJob` 会捕获主体抛出的任何异常并记录下来，同时在任务栏上把该次运行标记为失败，因此失败绝不会让界面卡在忙碌状态。只有在捕获后还需要先做某些特定处理时，才在主体内捕获，例如清理已挂载的映像，然后重新抛出。

```powershell
Write-WinUtilLog -Level "ERROR" -Component "Install" -Message "winget install failed: $($_.Exception.Message)"
```

日志条目与控制台诊断信息都写入同一个会话文件
`%LocalAppData%\winutil\logs\winutil_<timestamp>.log`。在 `Start-Transcript` 占用该文件期间，`Write-WinUtilLog` 通过主机写入，这样 transcript 就能捕获到日志条目，而无需与之竞争直接写文件。

## 配置加载

启动时，Winutil 会加载所有配置：

# Load JSON configs
$sync.configs = @{}

## 界面更新模式

控件只能由拥有窗口的那个线程操作，因此后台工作通过 `Invoke-WPFUIThread` 访问它们：

```powershell
Invoke-WPFUIThread -Parameters @{ Count = $installed.Count } -ScriptBlock {
    param($Count)
    $sync.WPFselectedAppsButton.Content = "Selected Apps: $Count"
}
```

加上 `-Async` 可以改为投递更新而不等待其完成。`Step-WinUtilJob` 与 Win11 Creator 的状态日志就是这样做的，这样逐项更新就永远不会拖慢工作线程。

**传值，而非闭包**：主体会在界面运行空间内重建，因此它通过 `-Parameters` 获取所需内容。若改为从工作线程传递脚本块，则会保留该工作线程的会话状态 —— 在异步投递时会丢失调用方的变量，而且每条命令的开销约为前者的二十倍，足以让一次复选框刷新变成肉眼可见的卡顿。

## 添加新功能

### 添加新应用程序

1. 编辑 `config/applications.json`：
```json title="config/applications.json"
{
  "WPFInstallNewApp": {
    "category": "Utilities",
    "content": "New App",
    "description": "Description of new app",
    "winget": "Publisher.AppName",
    "choco": "appname"
  }
}
```

2. 重新编译：`.\Compile.ps1`
3. 该应用会自动出现在 Install（安装）选项卡中

### 添加新优化项

1. 编辑 `config/tweaks.json`：
```json title="config/tweaks.json"
{
  "WPFTweaksNewTweak": {
    "Content": "New Tweak",
    "Description": "What it does",
    "category": "Essential Tweaks",
    "registry": [
      {
        "Path": "HKLM:\\Path\\To\\Key",
        "Name": "ValueName",
        "Type": "DWord",
        "Value": "1",
        "OriginalValue": "0"
      }
    ]
  }
}
```

2. 重新编译：`.\Compile.ps1`
3. 优化项会出现在 Tweaks（优化）选项卡中

### 添加新函数

1. 在 `functions/public/` 或 `functions/private/` 中创建文件：
```powershell
# functions/public/Invoke-WPFNewFeature.ps1
function Invoke-WPFNewFeature {
    <#
    .SYNOPSIS
    Does something new
    #>
    # Implementation
}
```

2. 文件名必须包含 “WPF” 或 “Winutil” 才能被加载
3. 重新编译：`.\Compile.ps1`

## 性能考量

**优化策略**：
- 延迟加载配置（仅在需要时加载）
- 对耗时操作使用运行空间（Runspace）
- 缓存开销较大的查询
- 尽量减少注册表读写
- 尽可能批量处理操作

## 安全考量

**安全措施**：
- 所有操作都记入日志
- 为撤销操作备份注册表
- 不存储凭据
- 开源（可审计）
- 数字签名（未来支持）

## 贡献指南

**代码规范**：
- 使用正确的 PowerShell cmdlet 命名（动词-名词）
- 包含基于注释的帮助
- 遵循现有代码风格
- 提交 PR 前充分测试
- 记录重大变更

**文件命名**：
- 公共函数：`Invoke-WPF*.ps1` 或 `Invoke-Winutil*.ps1`
- 私有函数：`Get-WinUtil*.ps1` 或 verb-WinUtil*.ps1`
- 必须包含 “WPF” 或 “Winutil” 才能被加载
