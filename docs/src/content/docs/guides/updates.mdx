WinUtil 提供三种更新模式，让你可以选择在本机上以多大的力度管理 Windows 更新：

![Image of Updates Tab](../../../assets/screenshots/updates-tab-new.png)

切换模式会调整系统范围的 Windows 更新行为。切换之后，请给 Windows 一点时间来应用策略；如果新状态没有立即生效，请做好重启的准备。

- **推荐**：优先保证稳定性，同时仍然接收安全更新
- **Windows 默认**：恢复标准的 Windows 更新行为
- **禁用更新**：阻止 Windows 更新，使用时务必极其谨慎

### Windows 默认

- **作用**：移除由 WinUtil 管理的 Windows 更新策略，恢复更新服务的启动设置，并重新启用更新计划任务。
- **适用场景**：希望由 Windows 正常管理更新的系统。
- **说明**：只会移除由 WinUtil 管理的值，其他 Windows 更新策略保持不变。如果更新错误仍然存在，请使用**配置**标签页中的重置选项来修复 Microsoft Update 组件。

### 推荐

- **作用**：应用一套更保守的更新策略，专为大多数用户设计。
- **功能更新**：延迟 **365 天**，以降低 Windows 重大改动带来中断的风险。
- **质量更新**：延迟 **4 天**，为早期问题暴露留出时间，同时仍能保持系统受到保护。
- **驱动程序**：从 Windows 质量更新中排除。
- **安装方式**：更新会自动下载，并在准备就绪可以安装时通知你。此设置不控制安装完成后的重启。
- **适用范围**：更新延迟策略适用于 Windows Pro、Enterprise 和 Education 版本。
- **为什么使用它**：这种模式在安全性和稳定性之间取得了最佳平衡，因此是大多数电脑的推荐选项。

### 禁用更新（强烈不推荐！）

- **作用**：禁用自动更新策略，停止并禁用更新服务，禁用更新计划任务，并清除已下载的更新文件。
- **适用场景**：需要临时保持更新关闭的高度受控或特殊用途系统。
- **警告**：这会让系统失去安全补丁，显著增加安全风险。
- **说明**：在某些情况下，Windows 服务堆栈可能会恢复更新组件。准备好重新接收更新时，请使用**恢复默认设置**。
- **建议**：除非你完全理解其中的取舍并且有明确的使用理由，否则请避免使用此模式。
